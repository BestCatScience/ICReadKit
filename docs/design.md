# 設計の判断

## 何を読むかを、暗証番号なしで読める範囲に限った

利用者証明用電子証明書は暗証番号なしで READ BINARY できる。氏名・住所は入っていない。暗証番号の照合は失敗するとロックに近づくので、構成例で試す理由がない。

- 代わりに捨てたもの：基本 4 情報の表示、残り回数の表示。データなしの VERIFY で残り回数を返すカードは多いが、このカードで回数を減らさないと確かめた一次資料が見つからなかった。

## 命令は SELECT と READ BINARY しか作れない

`CommandAPDU` の初期化子を非公開にし、組み立て関数を 3 つだけ置いた。許す命令の集合はテストで固定している。実行時の検査で落とす作りは、SDK の中で組み込み先のアプリを落とすことになるので採らなかった。

## カードへの口を差し替えられる形にした

`CardTransport` を挟み、Core NFC、テストの台本、デモカードが同じ `JPKIReader` を通る。読み取りの手順（分割読み出し、ヘッダからの長さ計算、状態語の扱い、空の応答で止まる）を、端末なしで全部テストできる。

## 期限切れは結果であってエラーではない

期限切れの証明書で例外を投げると、組み込み先は「読めなかった」と「読めたが期限切れ」を区別できない。`CertificateSummary.validity(at:)` で返し、どう伝えるかはアプリに任せた。

## エラーは「アプリが次にすること」で分けた

Core NFC のエラーコードをそのまま渡さず、取り消し・時間切れ・離れた・別のカード・設定漏れなど、組み込み先が取る行動ごとに分けた。対応していないコードは `system(code:)` で残し、落とさない。

## 設定漏れは読み取り前に知らせる

Info.plist の利用目的や AID が欠けていると、Core NFC はシートを開いた後に分かりにくいエラーを返す。`availability()` で事前に理由付きで返す。シミュレーターでも設定漏れを先に報告する順にしてある。

## 配布物はライブラリの互換を保つ設定で作る

`BUILD_LIBRARY_FOR_DISTRIBUTION` を有効にした XCFramework にした。公開した列挙型は固定せず、後でケースを足せるようにしてある。その代わり組み込み先は `@unknown default` を書く必要がある（サンプルアプリで実際に必要になった）。公開 API は `api/ICReadKit.json` を基準に、壊れる変更を CI で止める。

## 依存は持たない

第三者のライブラリを入れると、組み込み先が同じものを入れたときに Bundle ID が衝突する（ITMS-90685）。DER の解析は必要な分だけ自前で書いた。

## 端末がなくても全部の画面を出せる

シミュレーターでは自動でデモカードに切り替わる。デモの証明書はその場で組み立てた架空のもので、実在の人のデータは入っていない。UI テストはこのデモカードで 4 通りの結果を確かめる。

## 両 OS を同じ設計にした

Android の SDK は Java で書き、iOS と同じ部品（命令の組み立て、差し替えられる送信口、証明書の解析、デモカード、計測イベント）を同じ名前で持つ。版とデモカードの識別子は検査とテストで揃え、サンプルアプリの識別子も揃えて、Maestro のシナリオを両 OS で共有する。

- Android の SDK を Java にしたのは、組み込み先が Java のアプリでも Kotlin の実行時ライブラリを持ち込まずに使えるようにするため。
- Android の読み取りモードにはシートがないので、「待っている間」を `Session` で表し、画面を離れたら `cancel()` で離脱として記録する。
- Compose のテスト用タグを識別子として外に出す設定（`testTagsAsResourceId`）で、iOS のアクセシビリティ識別子と同じ名前で Maestro から見つけられるようにした。
- AAR には組み込み先の難読化向けの keep ルールを同梱し、サンプルのリリース版を難読化してビルドすることで、そのルールが効くことを確かめている。
- Android Lint は警告もエラーとして扱う。`Set.of` のように D8 が古い OS 向けに補う API は通り、補えない API は止まることを確かめた。

## Wallet の経路は「開けずに渡す」

iPhone のマイナンバーカード（Apple Wallet）の経路を足した。Wallet の応答は組み込み先のサーバーの鍵で暗号化されていて、SDK は開けない。それを利点として扱い、SDK は要求を組み立てて暗号化されたデータを渡すだけにした。真偽はサーバーで確かめる、という国内外の流れにも合う。

- 個人番号を要求する手段を作らなかった。型にケースがなく、検査でも `documentNumber` を止める。
- 年齢の下限（`.ageAtLeast`）を用意し、生年月日を取らずに済む道を先に見せた。
- nonce の長さは SDK で 16〜64 バイトに制限し、Wallet を開く前に止める。
- PassKit を呼ぶ部分は差し替えられる形にして、entitlement がなくても要求の組み立てとエラーの変換をテストできるようにした。PassKit の項目は参照のたびに新しいオブジェクトになるため、テストでは記述子が持つ項目そのもので照合する。

## 真偽はサーバーで確かめる

国内外の本人確認の事業者は、端末で読み、サーバーで確かめる形にそろっている（ドイツの AusweisApp、Regula のサーバーでの再検証、Entrust の結果を Webhook で返す作り）。端末の中の判定は、改ざんされた端末や注入攻撃で偽れるためだ。

- SDK に、証明書そのものを返す口（`readCertificateForVerification`）を足した。既定の `readCertificateSummary` はこれまでどおり要約だけを返し、証明書が外に出るのは組み込み先がはっきり選んだときだけにした。
- 参照実装の検証サーバーを、先方のバックエンドと同じ Go で書いた。外部の依存は持たない。
- 失効の確認は、プラットフォーム事業者との契約がないとできない。できないことを「確認済み」に見せないよう、`not_checked` を契約の値として定義した。
- カードを持っていることの証明は、暗証番号による署名が要るので入れていない。入れるなら、暗証番号の入力画面、残り回数の表示、ロック時の案内を含めた設計変更として扱う。
